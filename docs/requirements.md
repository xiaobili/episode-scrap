## 问题陈述

剧集收藏者从各种渠道拿到的一批剧集文件，文件名形态高度不一致：西式发布组命名（`Breaking.Bad.S01E03.1080p.BluRay.x264-DEMAND`）、中文命名（`绝命毒师 第1季 第03集.mp4`）、裸集号（`03.mkv`）、多集合并（`S01E01-E02`）、以及大量无关噪声（分辨率、编码、音轨、字幕组、语言标签）。这些文件丢进 Plex / Emby / Jellyfin 后，媒体服务器要么识别不出剧集，要么把同一部剧拆成好几条，海报、简介、播出日期全部缺失。

人工处理这批文件有三个具体痛点：

1. **改名前不知道会改成什么。** 批量重命名一旦执行就动了真实文件，一次规则写错可能让几百个文件失去原有命名，而原文件名往往承载着唯一可回溯的信息。
2. **元数据得一个文件一个文件补。** 即便改对了名字，NFO、海报、剧集标题仍要逐个去元数据站点查、逐个手写。
3. **文件不一定在本地。** 主力库常常挂在云盘上（通过 OpenList 聚合阿里云盘 / 115 / 百度网盘等），普通桌面重命名工具根本触达不到，下载到本地再传回去的时间成本比手工改还高。

此外还有一段被现有工具忽略的收尾工作：改完名、补完元数据之后，媒体服务器不会自己知道，必须有人再去点一次「扫描媒体库」。

## 解决方案

一个浏览器里的流水线工作台，把「扫描 → 解析 → 刮削 → 重命名 → 刷新媒体库」串成一条可回退的链路：

- **双重插件化**：数据源（文件在哪：本地目录 / OpenList 云盘）与媒体源（元数据从哪：TMDB）各自独立扩展，上层业务只依赖抽象契约。云盘文件通过 OpenList 的 HTTP API 原地改名、直接上传 NFO 与 STRM，不需要挂载、不需要下载。
- **所有写操作先预览**：重命名先出 diff 预览（可执行 / 冲突 / 跳过 / 错误四态），执行后保留撤销记录；单文件失败不拖垮整批。
- **解析结果可人工接管**：自动解析给出剧名、年份、季、集、分辨率、编码、发布组与置信度，用户逐个修正或整批重解析；目录结构（`Season 01`、`第1季`）参与推断。
- **任务化执行**：重命名作为后台任务逐项推进，WebSocket 实时推送进度与逐项结果，离开页面不中断，失败项可一键重试，整批可撤销。
- **一次点完的收尾**：配置好 Jellyfin 后，直接在「刷新媒体库」页勾选库触发扫描，同步元数据、海报与 STRM。

## 用户故事

### 数据源与扫描

1. 作为剧集收藏者，我希望在扫描页用「本地 / OpenList」切换数据源，以便用同一套流程处理本机目录和云盘文件。
2. 作为剧集收藏者，我希望本地目录只能从白名单根目录开始逐级下钻，以便不会误扫到系统目录或权限外路径。
3. 作为剧集收藏者，我希望看到当前可用的全部数据源（本地 + 已配置的 OpenList 实例），以便知道哪些库可以扫。
4. 作为剧集收藏者，我希望选中 OpenList 实例后默认从其挂载路径开始浏览，以便不用记完整云盘路径。
5. 作为剧集收藏者，我希望在 OpenList 目录树上强制刷新，以便刚上传到云盘的文件立刻可见，不被服务端缓存挡住。
6. 作为剧集收藏者，我希望云盘目录以「只列子目录」的方式逐层下钻，以便在几千个文件的库里快速定位目标季。
7. 作为剧集收藏者，我希望扫描时可以勾选「含子目录」，以便一次覆盖整剧的多层目录结构。
8. 作为剧集收藏者，我希望扫描结果明确区分视频与非视频，并能一键「仅看视频」，以便不被字幕、封面、nfo 干扰。
9. 作为剧集收藏者，我希望按文件名关键词过滤扫描结果，以便在大目录里定位某一集。
10. 作为剧集收藏者，我希望每条结果显示文件大小与修改时间，以便确认选中的是想要的那个版本。
11. 作为剧集收藏者，我希望扫描完成后看到文件总数、视频数、非视频数与耗时，以便判断是否需要缩小扫描范围。
12. 作为剧集收藏者，我希望对同一目录重新扫描时旧记录与旧匹配被清理，以便不出现重复条目或过期的刮削结果。
13. 作为剧集收藏者，我希望文件列表分页展示，以便上千文件时不卡顿。
14. 作为剧集收藏者，我希望 OpenList 登录态过期时系统自动重登并重试一次，以便长时间操作不中断。
15. 作为剧集收藏者，我希望服务端限流或 5xx 时按指数退避重试，弱网下也能完成扫描与上传。
16. 作为剧集收藏者，我希望云盘路径写错或不存在时得到明确的错误提示，以便快速改正。
17. 作为剧集收藏者，我希望扫描结果能跨页面持久（刷新浏览器后仍在），以便中断后接着做。
18. 作为剧集收藏者，我希望扫描后进入解析页时不需要重新选文件，以便流程连贯。

### 解析

19. 作为剧集收藏者，我希望系统自动从文件名提取剧名、年份、季、集，以便不用手工填表。
20. 作为剧集收藏者，我希望支持西式发布组命名（`S01E03`、`1x03`、`EP03`），以便覆盖绝大多数下载来源。
21. 作为剧集收藏者，我希望支持中文命名（`第1季 第3集`、`第3集`），以便国产剧、日韩剧也能识别。
22. 作为剧集收藏者，我希望支持没有季信息的裸集号（`03.mkv`、`03.1080p.mkv`、`03v2.mkv`），以便缺季目录的散文件也能解析。
23. 作为剧集收藏者，我希望识别多集合并（`S01E01-E02`）并保留集尾号，以便命名时能体现范围。
24. 作为剧集收藏者，我希望电影文件名里的年份（`2023`）不被误判成集号，以便不会把电影当剧集处理。
25. 作为剧集收藏者，我希望标题清洗能去掉分辨率、编码、音轨、语言、字幕组等噪声，以便刮削搜索命中率高。
26. 作为剧集收藏者，我希望从目录结构补全信息（`Season 01`、`S01`、`第1季` 推导季号，上一层目录名推导剧名），以便文件名里只有集号时也能对齐。
27. 作为剧集收藏者，我希望目录推导出的剧名优先于文件名推导的剧名，以便文件名被改乱（如 `01.mkv`）时仍能正确刮削。
28. 作为剧集收藏者，我希望通用目录名（`TV`、`Downloads`、`电视剧`、`美剧` 等）不被当成剧名，以便标题不出现「下载」这类无意义词。
29. 作为剧集收藏者，我希望看到每个文件的解析置信度（百分比与颜色分级），以便快速判断哪些需要人工复核。
30. 作为剧集收藏者，我希望看到本页平均置信度，以便判断整批解析质量。
31. 作为剧集收藏者，我希望逐个修正剧名、年份、季、集、集尾、集标题、分辨率、编码、发布组，以便解析失手时人工兜底。
32. 作为剧集收藏者，我希望修正后能一键保存并跳到下一条，以便连续处理一批文件。
33. 作为剧集收藏者，我希望用 j / k 键切换上一条 / 下一条，以便不碰鼠标快速过一遍。
34. 作为剧集收藏者，我希望单条「重新解析」覆盖我改坏的结果，以便后悔时能回到自动结果。
35. 作为剧集收藏者，我希望「批量自动解析」一次重跑当前列表，以便规则改进后整批刷新。
36. 作为剧集收藏者，我希望解析页按「全部 / 待确认 / 未解析」分栏，以便专注处理有问题的文件。
37. 作为剧集收藏者，我希望未解析的文件仍保留在列表里并标为错误态，以便知道哪些被跳过了。
38. 作为剧集收藏者，我希望一键复制原始文件名，以便去别处搜索核对。

### 刮削

39. 作为剧集收藏者，我希望未配置 TMDB Key 时在刮削页与媒体源设置里看到明确引导，以便知道为什么搜不到东西。
40. 作为剧集收藏者，我希望输入剧名回车搜索（同时支持中文名与原名），以便找到目标剧集。
41. 作为剧集收藏者，我希望搜索结果显示海报、年份、评分、简介与季数，以便区分同名的不同版本。
42. 作为剧集收藏者，我希望选择剧集后可切换季，以便多季剧精确对齐。
43. 作为剧集收藏者，我希望看到该季的集列表（集号、标题、播出日期、剧照），以便确认季集数据是否完整。
44. 作为剧集收藏者，我希望本地文件能按集号自动对齐到剧集集数，并显示「已匹配 / 未匹配」及原因（缺季集信息、该季不存在、该季没有第 N 集），以便知道哪几条需要手动处理。
45. 作为剧集收藏者，我希望未匹配项能用季号兜底参数指定季，以便文件名缺季时也能匹配。
46. 作为剧集收藏者，我希望匹配结果落库后可跨页面使用，以便重命名页与任务页都能读到剧集标题、简介、评分、剧照。
47. 作为剧集收藏者，我希望对同一文件重复匹配时覆盖旧结果，以便换剧换季时不残留脏数据。
48. 作为剧集收藏者，我希望匹配成功后文件状态变为「已匹配」，以便在流水线里追踪进度。
49. 作为剧集收藏者，我希望刮削阶段不会偷偷改名或写文件，以便整个过程可控。

### 重命名

50. 作为剧集收藏者，我希望在可视化模板编辑器里改命名模板并实时看到样例渲染结果，以便不用反复试错。
51. 作为剧集收藏者，我希望模板变量有白名单校验，写错变量名时立刻报错并列出可用变量，以便不会等到执行才失败。
52. 作为剧集收藏者，我希望季、集、集尾、年份支持补零格式（如两位季集），以便生成 `S01E03` 这种媒体服务器认得的名字。
53. 作为剧集收藏者，我希望生成的文件名自动剔除非法字符、折叠多余分隔符、限制长度，以便跨平台安全。
54. 作为剧集收藏者，我希望缺季或集时该条被跳过并说明原因，而不是生成半成品名字。
55. 作为剧集收藏者，我希望预览以 diff 形式对比原名与新名，以便一眼看出改了什么。
56. 作为剧集收藏者，我希望预览把冲突单独标出（目标文件已存在 / 同一批内重名），以便执行前处理干净。
57. 作为剧集收藏者，我希望名称没变化的文件被标为跳过，以便不产生无意义的写操作。
58. 作为剧集收藏者，我希望「仅预览」绝对不写盘，以便先看清楚再决定。
59. 作为剧集收藏者，我希望执行前自选冲突策略（跳过 / 自动加序号），以便两种取舍都能覆盖。
60. 作为剧集收藏者，我希望自动加序号时依次尝试 `(1)`、`(2)`… 且仍冲突就放弃该条，以便不会覆盖别人文件。
61. 作为剧集收藏者，我希望执行前看到将处理多少条，并二次确认，以便避免误点。
62. 作为剧集收藏者，我希望只对勾选的文件执行，以便小批量试水。
63. 作为剧集收藏者，我希望重命名保留原扩展名，以便不会把 mkv 变成无扩展名文件。
64. 作为剧集收藏者，我希望跨数据源（本地 / 云盘）用同一套预览与执行逻辑，以便行为一致。
65. 作为剧集收藏者，我希望单条失败时其余继续，且失败原因逐条可见，以便不会因为一个坏文件卡死整批。
66. 作为剧集收藏者，我希望重命名成功后文件状态变为「已重命名」并记录新名，以便确认结果。
67. 作为剧集收藏者，我希望随时撤销最近一次重命名任务，把所有文件恢复原名，以便出错能回退。
68. 作为剧集收藏者，我希望撤销时逐条报告成功与失败数，并列出失败原因，以便知道哪些没恢复。
69. 作为剧集收藏者，我希望撤销不会删掉已写入的 NFO / 海报 / STRM，以便不会误删有用元数据。
70. 作为剧集收藏者，我希望撤销后文件回到「已匹配」状态，以便可以换个模板重来。

### NFO、海报与 STRM

71. 作为剧集收藏者，我希望勾选后为每个匹配到的文件生成同名 NFO，以便媒体服务器读到剧集标题、简介、播出日期、评分、季集。
72. 作为剧集收藏者，我希望 NFO 缺集标题时回退为「第 N 集」，以便不会出现空标题。
73. 作为剧集收藏者，我希望 NFO 写入失败不影响重命名结果，以便元数据问题可以事后补。
74. 作为剧集收藏者，我希望勾选后下载该集剧照为 `<同名>-thumb.jpg`，以便媒体库有缩略图。
75. 作为剧集收藏者，我希望剧照下载失败只记录警告，以便不影响主流程。
76. 作为剧集收藏者，我希望勾选后为每个文件生成同名 `.strm`，以便媒体服务器通过链接串流而不读原文件。
77. 作为剧集收藏者，我希望 STRM 模板变量（服务地址、站内路径、原始路径、文件名）有校验，且必须包含路径变量，以便不会生成空链接。
78. 作为剧集收藏者，我希望站内路径自动 URL 编码并去掉前导斜杠，以便中文与空格路径也能拼出可访问的 URL。
79. 作为剧集收藏者，我希望 STRM 有三种输出位置：与视频同目录（alongside）、按剧名/季归档到媒体库目录（library）、按源目录镜像到目标根（mirror），以便适配不同的媒体服务器布局。
80. 作为剧集收藏者，我希望镜像模式在源路径不在扫描根之内时自动回退到按剧名归档，以便不会写到意外的位置。
81. 作为剧集收藏者，我希望用规则表把不同源目录投递到不同目标（本地目录或另一个 OpenList 实例），以便一个实例管理多块库。
82. 作为剧集收藏者，我希望规则按路径段边界做最长前缀匹配，以便 `/media/美剧` 不会误命中 `/media/美剧备份`。
83. 作为剧集收藏者，我希望投递到云盘时自动逐级创建缺失目录，以便不用手工建好目录树。
84. 作为剧集收藏者，我希望 STRM 在重命名之后生成，内容反映新路径，以便链接不指向已失效的旧文件名。
85. 作为剧集收藏者，我希望本地数据源的 STRM 写入文件的绝对路径直链，云盘数据源写入按模板拼出的可访问 URL，以便两种源都能被串流。

### 任务中心

86. 作为剧集收藏者，我希望重命名提交后立刻返回任务号并转到后台执行，以便不阻塞浏览器。
87. 作为剧集收藏者，我希望离开任务页后任务继续运行，以便不用守着进度条。
88. 作为剧集收藏者，我希望任务详情实时推送进度（总数、完成、失败）与最近一条逐项结果，以便知道卡在哪。
89. 作为剧集收藏者，我希望任务列表可按状态筛选，以便只关心运行中或失败的。
90. 作为剧集收藏者，我希望看到任务使用的模板与开关（NFO / 海报 / STRM），以便复盘当时用的什么规则。
91. 作为剧集收藏者，我希望失败项一键重试并生成一个新任务，以便不重跑已成功的文件。
92. 作为剧集收藏者，我希望原任务记录不被改写，以便保留历史。
93. 作为剧集收藏者，我希望任务级错误单独展示，以便区分「整批失败」和「个别项失败」。

### 刷新媒体库

94. 作为媒体库运维者，我希望在设置里填 Jellyfin 地址与 API Key 并测试连接，测试结果显示服务器名与版本，以便确认配置正确。
95. 作为媒体库运维者，我希望刷新页列出 Jellyfin 上的全部媒体库，以便勾选要更新的库。
96. 作为媒体库运维者，我希望一次勾选多个库一起刷新，以便批量收尾。
97. 作为媒体库运维者，我希望刷新结果按库逐个报告成功或失败原因，以便部分失败时知道补哪一个。
98. 作为媒体库运维者，我希望本会话的刷新记录留在页面上，以便确认刚才点过哪些库。
99. 作为媒体库运维者，我希望未配置 Jellyfin 时看到引导而不是报错，以便知道下一步做什么。

### 设置与安全

100. 作为管理员，我希望 TMDB Key 只保存在服务端并加密存储，前端只能看到「是否已配置」，以便密钥不外泄。
101. 作为管理员，我希望 OpenList 密码加密入库且编辑时留空表示不修改，以便不会误清空凭证。
102. 作为管理员，我希望 OpenList 实例支持新增、编辑、删除、测试连接，并可配置挂载路径、超时、并发，以便管理多个网盘账号。
103. 作为管理员，我希望 OpenList 服务地址必须是合法的 http/https URL，以便挡住 SSRF 式的错误配置。
104. 作为管理员，我希望修改或删除实例后旧连接缓存立刻失效，以便改完配置马上生效。
105. 作为管理员，我希望本地白名单只接受绝对路径，且所有本地访问都做归一化与边界校验，以便挡住路径穿越。
106. 作为管理员，我希望 OpenList 并发、超时、重试有取值范围校验，以便不会配出把服务端打挂的参数。
107. 作为管理员，我希望 STRM 模板与目标目录在保存时就校验，以便不会等到执行任务才炸。
108. 作为管理员，我希望设置项先读数据库、没有则回落到环境变量，以便容器部署时用环境变量兜底、界面上仍可覆盖。
109. 作为管理员，我希望系统不提供任何删除远端文件的接口，以便工具不可能误删媒体文件。

### 非功能

110. 作为剧集收藏者，我希望扫描 1000 个本地文件在数秒内完成，以便大库也能用。
111. 作为剧集收藏者，我希望云盘操作受超时与重试约束，单文件失败不影响同批其他文件，以便弱网下仍可推进。
112. 作为剧集收藏者，我希望界面在窄屏下仍能完成全流程，以便在平板或分屏下操作。
113. 作为剧集收藏者，我希望每个页面顶部能一眼看出当前处于流水线的哪一步、各步还差多少条，以便知道下一步该做什么。

## 实现决策

### 术语与领域模型

| 术语 | 含义 |
|---|---|
| MediaFile | 一条被扫描到的文件记录，含数据源坐标（source_type / source_ref / scan_root / openlist_id）、原始名、大小、修改时间、解析结果、置信度、流水线状态（pending / parsed / matched / renamed / error） |
| DataSource | 文件操作抽象：本地文件系统、OpenList 云盘 |
| Provider | 元数据来源抽象：当前仅 TMDB |
| ScrapeMatch | 一条文件与剧集季集的匹配结果（file_id 唯一），携带剧名、年份、集标题、简介、播出日期、评分、海报与剧照地址 |
| RenameHistory | 一次重命名的前后路径映射，按任务聚合，带 rolled_back 标记，是撤销的唯一依据 |
| TaskRecord / TaskItem | 后台任务的批次头与逐项记录 |
| STRM | 指向媒体源的文本链接文件，供媒体服务器串流 |
| 置信度 | 解析结果的完整度评分（0–100），仅用于展示与分诊，不作为阻断条件 |

### 架构决策

1. **双插件体系分离**：DataSource 回答「文件在哪」，Provider 回答「元数据从哪」。业务层（解析、匹配、预览、执行、回滚）只依赖这两个抽象，不出现 `if 本地 / if 云盘` 的分支。
2. **DataSource 契约**：`list_dir(path, recursive, refresh)`、`get_file(path)`、`rename(path, new_name) → 新路径`、`batch_rename(items)`、`upload(dir, bytes, filename)`、`mkdir(path)`、`exists(dir, name)`、`join(dir, name)`。`exists` 是冲突检测的唯一入口，因此各数据源自行定义「存在」语义：本地用文件系统判定，云盘用列目录判定，列目录出错时保守返回「不存在」，由 rename 自身再做一次兜底。
3. **统一文件条目**：所有数据源返回同一形状（名称、完整路径、大小、是否目录、修改时间）。本地时间戳产出 ISO 字符串，云盘沿用服务端返回的原始时间字符串。
4. **数据源工厂 + 实例级缓存**：云盘数据源按实例 ID 缓存，以便复用登录态与连接池；实例被更新或删除时主动清缓存，避免旧凭证继续生效。
5. **OpenList 客户端语义**（决定错误处理行为）：
   - 懒登录：首次请求前登录，Token 只存后端内存。
   - Token 失效：HTTP 401 或响应体 `code == 401` 时清 Token、重登、重试一次；第二次仍 401 直接抛鉴权错误，不继续退避。
   - 限流/服务端故障：429 与 5xx 按 `0.5 × 2^n` 指数退避，单次等待上限 30 秒，重试次数来自设置。
   - 超时：同样退避重试，用尽后报 504 语义的错误。
   - 上传：`File-Path` 请求头必须 URL 编码（HTTP 头只能承载 ASCII），正文为 `application/octet-stream`。
   - 登录失败直接判为鉴权错误，不进入退避循环。
6. **扫描策略**：本地路径先过白名单（绝对路径 + 归一化 + 路径段边界判定），云盘路径必须以 `/` 开头；扫描按（数据源类型 + 扫描根 + 实例）清理同批旧记录与旧匹配后重建，保证重启扫描幂等；非视频文件也入库但标记为非视频，只做展示，不参与解析、匹配与重命名。
7. **扫描不发解析请求**：解析是独立动作，由用户在解析页显式触发（单条重解析或整批解析）。扫描页文案宣称的「自动解析」与实现不符，见「补充说明」。

### 解析决策

8. **匹配优先级**（从高到低）：`S01E01(-E02)` → `1x02` → `第N季…第M集` → `第N集` → `EPn` → 裸数字。裸数字需排除「第」前缀与「Season / Series」词尾，且数值 ≥ 1，避免把电影年份或分辨率数字当集号。
9. **标题清洗**：先剥离方括号/圆括号内容，再剥离噪声词表（BluRay、WEB-DL、HDTV、x264/x265/HEVC、DTS/AC3/AAC、HDR/DV、10bit、中字/双语/国语/粤语…），再折叠点号与分隔符、去掉尾部孤立的数字段。
10. **目录提示**：父目录若形如 `Season 01` / `S01` / `第1季`，作为季来源；再上一层若非通用目录名（TV、Downloads、电视剧、美剧…），作为剧名来源，且**目录剧名覆盖文件名剧名**；目录只有剧名没有季目录时，季默认 1，但文件名显式给出的季优先。
11. **置信度**：标题 40 + 季 25 + 集 25 + （年份或发布组）10，上限 100。前端按 ≥85 / ≥60 / 其余 三档着色。
12. **解析失败即错误态**：季与集都取不到时把状态置为 error，仍保留记录等待人工填写；人工修正任一季度字段后状态回到 parsed。

### 刮削决策

13. **Provider 契约**：`search(query, year)`、`get_show(show_id, season)`、`close()`。TMDB 固定 `zh-CN`，图片统一取 w500 尺寸。
14. **匹配是用户显式选择**：不做设计文档 6.2 的候选自动打分与阈值筛选。用户选定剧集与季之后，后端按文件逐条取该季详情（按季缓存，避免重复请求），按集号精确对齐；不做模糊匹配，不做跨季回退。
15. **匹配幂等**：同一文件的匹配结果唯一，重复匹配为覆盖更新，并同时把文件状态推进到 matched。
16. **季兜底**：文件缺季号时可用请求里的季参数兜底；仍缺季或集则直接判为未匹配并给出原因文案。

### 重命名决策

17. **模板变量白名单**：title、year、season、episode、episode_end、episode_title、resolution、codec、release_group。仅季、集、集尾、年份允许格式说明符（如两位补零）；其余变量带格式符直接判非法。
18. **渲染规则**：渲染前要求季与集非空；渲染后剔除非法字符（`<>:"/\|?*` 与控制字符）、把连续分隔符折叠为单个 ` - `、压缩空白、去首尾空白与标点、截断到 200 字符；结果为空则报错。扩展名永远沿用原文件。
19. **预览四态**：ready（可执行）、conflict（同批目标名重复 / 目标已存在）、skipped（非视频、缺季集、缺剧名、名称未变化）、error（模板非法、数据源检查失败）。预览阶段只读，不写任何文件。
20. **执行前重算**：执行时以同一模板重跑一次预览，仅采纳 ready；冲突策略为 skip 时丢弃冲突项，为 suffix 时从 `(1)` 递增到 `(49)` 找第一个不存在的名字，找不到则放弃该条。
21. **提交即落库**：任务头与逐项记录先落库，再启动后台协程，前端立刻拿到任务号。任务按（实例）缓存数据源，逐项串行执行。
22. **事务顺序**（关键）：重命名成功 → 立即写撤销记录并更新文件坐标（source_ref、原始名、状态）→ 再写 NFO → 再下剧照 → 最后写 STRM。后三步失败只记警告，不把该项标失败，也不回滚重命名，因为 NFO / 剧照 / STRM 都可以重新生成，而重命名已不可「免费」重来。
23. **撤销语义**：不传任务号时取最近一条未撤销记录所属的任务；把新路径按原 basename 改回，标记已撤销，文件坐标还原、状态回退到 matched、清空新名；NFO / 剧照 / STRM 一律保留；逐条提交，最后汇总成功数、失败数与失败原因。
24. **冲突的唯一性以目录为界**：所有冲突检测都限定在文件所在父目录内，不支持跨目录移动（重命名永远是原地改名）。

### NFO / 剧照 / STRM 决策

25. **NFO 结构**：`<episodedetails>` 下写 title（缺则「第 N 集」）、showtitle、season、episode、plot、aired、rating、year；两空格缩进；UTF-8；与视频同名同目录。
26. **剧照**：只在勾选时下载，取该集剧照存为 `<同名>-thumb.jpg`，走数据源上传接口，因此云盘也能写入。
27. **STRM 模板变量**：base_url、path、raw_path、filename；必须包含 path 或 raw_path；一律不支持格式说明符；path 做 URL 编码并去掉前导斜杠（避免模板里的 `/` 拼成双斜杠）；本地源直接写新路径本身，云盘源按模板拼可访问 URL。
28. **STRM 输出模式**：alongside 与视频同目录；library 按 `剧名 / Season NN` 归档；mirror 按源目录相对扫描根镜像；mirror 无法求相对路径时回退 library；library / mirror 缺目标根目录直接报错。
29. **STRM 规则表**：规则为「源路径 + 目标类型（本地/云盘实例）+ 目标目录」；匹配按路径段边界取最长前缀，命中后相对目录原样拼到目标目录下；云盘目标逐级 mkdir 后上传；规则在设置保存时做绝对路径、去重、实例有效性校验。
30. **生成时机**：STRM 在重命名之后生成，使用新路径，因此不会产生指向旧名的死链。

### 任务与实时通道决策

31. **任务状态机**：pending → running → completed；批次级只有这三态，逐项才有 success / failed / skipped。失败数 > 0 不改变批次为 failed，避免「部分成功」被当成整体失败。
32. **进度推送**：WebSocket 按任务号分房间广播，payload 含任务级计数与可选的最近一项结果；连接建立时先补发一次快照，保证晚到的客户端也能看到当前状态。
33. **重试不改历史**：重试以原任务的失败项新建一个任务（继承模板与 NFO/海报/STRM 开关），原任务记录保持只读。

### 配置与安全决策

34. **配置分层**：环境变量提供默认值，数据库设置项覆盖之；读取统一走「先查库、再回落到配置」。这一层顺序让容器部署可用环境变量起步，界面仍可临时覆盖。
35. **密钥处理**：TMDB Key、OpenList 密码、Jellyfin Key 均以对称加密入库；出参只返回布尔「是否已配置」，永不返回明文；编辑时密码留空表示不修改。
36. **路径安全**：本地白名单必须是绝对路径，所有本地访问先归一化再做路径段边界判定，越界一律 403；STRM 目标目录与规则目标同样要求绝对路径。
37. **不封装删除**：OpenList 的删除接口不封装、不暴露，工具层面消除误删可能。
38. **参数范围**：云盘并发 1–10、超时 5–300 秒、重试 0–10；越界在保存时即拒绝。

### 前端信息架构决策（相对 design.md 的变更）

39. **路由从 6 个扩为 7 个**：扫描 / 解析 / 刮削 / 重命名 / 刷新媒体库 / 任务中心 / 设置。刷新媒体库是新增的收尾步骤，对应 Jellyfin 集成。
40. **流水线导航**：前四步用步骤条串起，并在顶部展示各步待处理条数（已扫描、已解析、已匹配、待重命名），让用户随时知道下一步该做什么。
41. **视觉与组件体系替换**：放弃 Element Plus，改为自研组件 + Tailwind v4 的原型化视觉（品牌标识、统计条、分页器、diff 文本、置信度仪表、抽屉/弹层、toast、选择菜单等），以便统一设计语言并减少组件库体积。
42. **单一工作流 store**：文件列表、选中集合、当前数据源与路径、预览结果、当前剧集详情集中在一个 store；切数据源或重新扫描时清空下游状态（预览与剧集详情），避免跨批次脏数据。

### 已知未接线项（必须显式记录的现状）

43. **批量重命名接口未接线**：DataSource 契约里的批量改名已实现，但任务执行仍逐文件调用单条改名，云盘请求数等于文件数。批量接口保留作为后续优化入口。
44. **并发参数未生效**：云盘并发与刮削并发可配置、有校验、也会持久化，但扫描递归与任务执行目前都是串行，参数尚未用于实际并发控制。
45. **多 Provider 未实现**：Provider 抽象与注册机制就绪，实际只有 TMDB 一个实现，接口只返回单一媒体源。
46. **自动匹配未实现**：设计文档的候选打分与置信度阈值选择未落地，改为用户显式选择剧集与季。

## 测试决策

### 什么算好测试

只断言外部可观察行为：HTTP 状态码与响应体、磁盘上真实产生的文件名与文件内容、WebSocket 推送的 payload 形状、配置读取的最终结果。不断言私有函数调用次数、内部字段顺序、实现细节。凡涉及外部网络（TMDB、真实 OpenList、Jellyfin）一律注入假传输层或假数据源，测试不依赖网络与真实凭证。

### 接缝划分（已与用户确认）

采用两层现成接缝，不新增第三层：

1. **HTTP API 接缝（主接缝）**：用 ASGI 客户端直连应用，跑完整业务链路——扫描 → 解析 → 匹配（假 Provider）→ 预览 → 执行 → 撤销，以及 STRM 三种模式与规则投递、任务重试、设置读写。这是覆盖「用户看到的行为」的最高点。
2. **DataSource 接缝**：用本地数据源配临时目录，验证改名、上传、冲突、目录创建这些文件系统语义；云盘侧行为在客户端层用假传输层验证（登录、401 重登、429 退避、上传头编码）。
3. **纯函数单测**：解析器、模板校验与渲染、STRM 模板校验与渲染保持无 IO 单测，不引入接缝。

### 需要覆盖的范围

- 解析器：西式/中文/交叉季集/多集/裸集号/EP 前缀/版本号后缀、电影年份不误判、目录提示优先级、通用目录名排除、非视频判定。
- 模板：正常渲染、缺集标题、未知变量拒绝、非数值变量拒绝格式符、缺季集拒绝、非法字符清洗与截断。
- 预览与执行：四态分布、非法模板 400、冲突跳过、加序号策略、撤销成功与文件缺失时的失败报告。
- 任务链路：NFO 写入失败不影响重命名、剧照下载、STRM 三种模式与规则建目录（本地与云盘两种目标）、失败项重试生成新任务、WebSocket 快照。
- 云盘客户端：登录失败、Token 失效重登一次、限流退避、上传 `File-Path` 编码、列目录递归。
- 设置：加密存取、并发/超时/重试边界、白名单绝对路径校验、STRM 规则校验、模板校验。
- Jellyfin：连接测试、媒体库列表、逐库刷新结果（部分失败仍返回逐项结果）。

### 现有先例

解析器 19 例、模板 7 例、任务链路 13 例（含预览三态、跳过与后缀策略、STRM 三模式、规则建目录、NFO 失败不失败重命名、撤销报告缺失文件、失败项重试）、STRM 12 例、云盘客户端 10 例、本地数据源 6 例、设置 14 例、Jellyfin 接口 5 例 + 客户端 6 例。新用例沿用同一套做法：ASGI 客户端 + 临时目录 + 假传输层。

### 待补覆盖（本次确认后应补）

- 扫描的白名单越界 403、云盘路径缺前导斜杠 400、同批旧记录与旧匹配的清理。
- 云盘 401 重登恰好一次、429 退避后成功、超时耗尽报错文案。
- STRM 规则的最长前缀匹配（`/media/美剧` 与 `/media/美剧备份` 的边界）。
- 设置项读取优先级（库覆盖环境变量）与「只返回 has_* 不返回明文」。

## 不在范围

- **多 Provider**：TVDB、豆瓣等媒体源接入（抽象已就绪，实现不在本期）。
- **自动匹配**：候选自动打分、置信度阈值自动选剧，以及无人工介入的批量刮削。
- **电影与综艺**：仅剧集；电影的年份/标题解析、综艺的多集结构不做特殊处理。
- **多集合并改名**：集尾号只能作为模板变量输出，不把 `E01-E02` 拆成两条记录。
- **用户体系**：登录、鉴权、多租户、操作审计；安全边界依赖部署侧网络隔离。
- **破坏性操作**：删除文件、回收站、清理空目录、批量删 NFO（云盘删除接口不封装）。
- **附属文件**：字幕、种子、图片的批量改名与关联。
- **前端 e2e**：Playwright 级别的浏览器自动化、真实服务器联调、性能基准。
- **桌面端与国际化**：桌面打包、多语言界面。

### 建议的修复优先级

1. **文案与实现对齐**：扫描页宣称「扫描后自动解析」，实际需要用户在解析页手动触发；要么在扫描成功后自动调用一次整批解析，要么修正文案。
2. **批量改名接线**：云盘批量库文件多时，逐文件改名会把请求数放大到文件数，接上批量接口能显著缩短任务时间。
3. **并发参数落地或下线**：当前并发配置有 UI、有校验、无效果，容易误导使用者；要么实现并发控制，要么从设置里移除。
